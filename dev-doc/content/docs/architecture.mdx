# Architecture & Database Schema

The AddisPay web platform operates as a decoupled, fullstack web application consisting of a Next.js 16 frontend talking to a Go REST API over HTTP/JSON.

## 📐 Backend Clean Architecture Flow

Each business domain in `backend/internal/` strictly follows clean separation of concerns:

```text
Request ──► HTTP Handler ──► Usecase (Domain Logic) ──► Repository (GORM) ──► PostgreSQL
```

1. **Delivery (`internal/<domain>/delivery/http`)**: Parses JSON / multipart form inputs, validates fields, and maps domain errors to standard HTTP status codes.
2. **Domain (`internal/<domain>/domain`)**: Defines core entity structs, interfaces, and business errors.
3. **Usecase (`internal/<domain>/usecase`)**: Implements business rules (e.g. slug generation, image compression, password hashing, audit log generation).
4. **Repository (`internal/<domain>/repository`)**: GORM database queries, transactions, and pagination.
